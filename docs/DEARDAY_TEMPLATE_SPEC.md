# DearDay 판매용 템플릿 규격

> 목적: DearDay 판매용 템플릿의 공통 렌더링·디자인·Asset·운영 규격을 정의한다.
> 이 문서는 ⑬ 관리자 페이지 및 ⑬-A 판매용 템플릿 확대 구현 시 기준으로 사용한다.
> 핵심 원칙: **새로운 디자인은 관리자에서, 새로운 기능/Renderer 능력은 개발에서** 처리한다.

## 0. 핵심 구조 원칙

- 실제 공개 초대장은 공통 `InvitationRenderer`가 사용자 데이터 + 템플릿 버전 + 디자인 설정 + Asset을 조합해 렌더링한다.
- 템플릿 전체를 한 장의 평면 이미지로 만들어 실제 초대장을 대체하지 않는다.
- 템플릿과 행사종류(eventKind)는 독립적이다. 행사/분위기 태그는 추천·검색·필터용일 뿐 사용을 제한하지 않는다.
- 운영 중 변경될 가능성이 높은 디자인/판매 설정은 가능한 한 코드에 하드코딩하지 않고 DB + 관리자 페이지에서 관리한다.
- 관리자에게 임의 HTML/JavaScript/CSS 업로드를 허용하는 범용 페이지 빌더는 지양한다.
- 공통 규격으로 표현할 수 없는 새로운 기능·레이아웃·인터랙션만 별도 코드 개발 대상으로 분리한다.

## 1. T-01 기본 페이지 렌더링 규격

- 공개 초대장은 모바일 우선 반응형 세로 스크롤 페이지로 구성한다.
- 기본 렌더링 영역은 `width: 100%`, `max-width: 540px`, 중앙 정렬을 기준으로 한다.
- 세로 길이는 고정하지 않고 콘텐츠에 따라 가변한다.
- 540px보다 큰 화면에서는 초대장 본문을 최대 540px로 유지한다.
- 특정 390px 고정 캔버스나 1080×1920 한 장 이미지 방식으로 제한하지 않는다.

## 2. T-02 대표사진(Hero) 규격

- 기본 Hero 사진 비율은 `4:5`를 기준으로 한다.
- 템플릿 특성에 따라 다른 비율 또는 별도 Hero 구조를 허용한다.
- 사용자 사진은 기본적으로 `object-fit: cover` 방식으로 표현한다.
- 사용자 사진과 고정 배경/프레임/장식은 별도 레이어로 분리한다.
- Hero용 원본은 고해상도를 사용하며 4:5 기준 1080×1350px급 이상을 권장한다.

대표사진 표현 방식은 다음 유형을 지원하는 방향으로 설계한다.

### 사진 중심형
- 사용자 대표사진 자체가 디자인의 중심인 템플릿.

### 컨셉 프레임형
- 한옥/한복, 중세 유럽, 어린이 판타지 등 고정 세계관이 상품 가치의 핵심인 템플릿.
- 사용자가 사진을 바꿔도 고정 컨셉 배경은 유지한다.
- 사용자 사진은 주인공 영역, 고정 배경은 액자/무대 역할을 한다.

### 포스터/일러스트형
- 대표사진 없이도 완성도가 유지되는 디자인을 지원한다.

## 3. T-03 대표사진 크롭·위치 조절

- 사용자 원본사진은 유지한다.
- 편집기에서 사진의 상하좌우 위치 이동과 확대/축소를 지원하는 방향으로 구현한다.
- 원본을 매번 물리적으로 잘라 새 파일로 저장하지 않고 `positionX`, `positionY`, `zoom` 등 렌더링 설정값을 저장한다.
- 사용자가 조정하지 않은 경우 중앙 정렬을 기본값으로 한다.

## 4. T-04 템플릿 디자인 레이어/Asset 구조

논리적으로 다음 레이어를 분리한다.

1. 고정 배경
2. 사용자 사진
3. 사진 마스크/클리핑 영역
4. 프레임·장식 Asset
5. 오버레이(빛, 질감, 그라데이션 등)
6. 실제 HTML 텍스트

- 이름, 날짜, 장소, 인사말 등 사용자 데이터는 디자인 이미지에 박아 넣지 않고 실제 텍스트로 렌더링한다.
- 마스크는 원본 사진을 변형 저장하는 것이 아니라 사진이 보이는 모양/영역을 정의한다.
- 필요 없는 레이어는 템플릿별로 생략 가능하다.
- 컨셉형 템플릿에서 사용자 사진을 교체해도 핵심 세계관은 유지되어야 한다.

## 5. T-05 디자인 Asset 제작 해상도

- 실제 렌더링 최대 폭은 540px이지만 디자인 Asset은 기본적으로 2× 해상도인 폭 1080px급을 기준으로 제작한다.
- 기본 4:5 Hero Asset 기준은 1080×1350px급을 권장한다.
- 초대장 전체 세로 길이를 하나의 초대형 이미지로 제작하지 않는다.
- 긴 배경은 섹션 Asset, 반복 가능한 배경, 장식 Asset 등으로 분리하여 모바일 로딩 비용을 관리한다.

## 6. T-06 콘텐츠 폭 체계

템플릿은 다음 3단계 폭 체계를 기본으로 한다.

- `Full`: 배경, Hero, 큰 사진 등 컨테이너 폭을 넓게 사용하는 영역
- `Content`: 갤러리, 달력, 지도, 계좌 등 일반 기능 영역. 기본 좌우 여백 약 20~24px
- `Text`: 인사말, 안내문 등 긴 글 영역. 기본 좌우 여백 약 32~40px

- 값은 절대적인 단일 하드코딩 규칙이 아니라 안전한 기본값이며 템플릿 설정으로 조정 가능하게 한다.

## 7. T-07 섹션 세로 간격

기본 spacing token은 다음을 기준으로 한다.

- `Compact`: 약 32px
- `Normal`: 약 56px
- `Large`: 약 80px

템플릿은 관계가 가까운 요소와 큰 분위기 전환 영역에 맞춰 token을 선택하거나 안전 범위 내에서 조정할 수 있다.

## 8. T-08 타이포그래피 규격

기본 역할은 다음 4단계로 구성한다.

- `Hero Title`: 약 28~36px 기본 범위
- `Section Title`: 약 20~24px 기본 범위
- `Body`: 약 15~17px 기본 범위
- `Caption/Small`: 약 12~14px 기본 범위

- 위 값은 초기 권장 범위이며 관리자 설정의 안전 범위는 구현 시 확정한다.
- 폰트 종류, 크기, 굵기, 행간, 자간, 정렬은 템플릿 DB 설정으로 관리하고 관리자 페이지에서 조정 가능하게 한다.
- 기본값 + 템플릿별 override 구조를 지향한다.
- 관리자가 지나친 값으로 디자인을 깨뜨리지 않도록 입력 범위/프리셋/검증을 제공한다.
- 실제 사용자 문구는 HTML 텍스트로 렌더링한다.
- 상업적 웹서비스 이용 권리가 확인된 폰트만 사용하며 라이선스 관리 정보를 추적할 수 있도록 한다.

## 9. T-09 색상·배경 규격

- 전체 배경색, 기본 글자색, 제목색, 포인트색, 버튼색, 버튼 글자색, 구분선색 등을 템플릿 설정으로 관리한다.
- 관리자는 컬러피커 등으로 변경할 수 있도록 한다.
- 배경 이미지 Asset과 필요 시 반투명 overlay를 지원한다.
- 판매용 템플릿의 완성도를 보호하기 위해 일반 사용자가 모든 디자인 색상을 임의 변경하는 기능은 기본 제공하지 않는다.

## 10. T-10 장식·프레임 Asset 배치

- 장식/프레임 Asset은 DB + Storage 기반으로 관리한다.
- 관리자는 정해진 슬롯을 기준으로 위치, 크기, 회전, 투명도, 레이어 순서 등을 조절할 수 있도록 한다.
- 예: Hero 좌측 상단, Hero 우측 하단, 섹션 상단, 배경 장식 등.
- 초기 관리자 페이지를 포토샵 같은 완전 자유형 디자인 에디터로 만들지 않는다.
- 규격화된 슬롯 + 세부 조정 방식으로 운영 복잡도와 오류를 줄인다.

## 11. T-11 갤러리 사진 규격

- 갤러리 최대 사진 수의 초기 기본값은 20장으로 한다.
- 최대 장수는 코드 상수가 아니라 운영 설정으로 변경 가능하도록 설계한다.
- 사용자는 원본 사진을 업로드하고 DearDay가 웹용 이미지를 자동 최적화하는 방향으로 구현한다.
- 갤러리에서는 최적화본/썸네일을 사용하고 필요 시 큰 이미지를 지연 로딩한다.
- 갤러리 레이아웃은 `grid`, `slider`, `vertical`, `polaroid` 등 지원 가능한 스타일을 템플릿 설정으로 선택할 수 있게 한다.
- 템플릿별 권장 사진 수를 별도로 안내할 수 있다.
- 클릭/탭 시 고화질 Lightbox를 제공한다.

## 12. T-12 스크롤 등장 애니메이션

화면에 계속 떠다니는 화면 효과와 별도로, 섹션이 viewport에 진입할 때 등장하는 스크롤 애니메이션을 지원한다.

- 예: `fade-up`, `fade-in`, `soft-slide`, `soft-zoom` 등.
- 템플릿별 ON/OFF, 종류, 속도, 이동거리, 지연시간 등을 설정 가능하게 한다.
- 관리자 페이지에서 안전 범위 내 설정 및 미리보기를 제공한다.
- 모바일에서는 `opacity` + `transform` 중심의 가벼운 애니메이션을 우선한다.
- OS/브라우저의 `prefers-reduced-motion` 설정을 존중한다.
- 과도한 움직임으로 읽기/터치를 방해하지 않는다.

## 13. T-13 공통 섹션 디자인 원칙

- 지도, 달력, 계좌, RSVP, 방명록, 갤러리 등 기능 로직은 공통 Renderer/공통 컴포넌트가 담당한다.
- 템플릿마다 기능 코드를 새로 복제하지 않는다.
- 템플릿은 섹션 배경, 제목 스타일, 버튼 스타일, 테두리/모서리, 구분선, 간격 등 디자인 설정을 적용한다.
- 원칙: **기능은 공통, 디자인은 템플릿 설정**.

## 14. T-14 섹션 순서·기본 표시 설정

- 템플릿별 섹션 목록, 기본 순서, 기본 ON/OFF를 설정 데이터로 관리한다.
- 관리자는 기본 구성을 변경할 수 있도록 한다.
- Renderer는 설정을 읽어 공통 섹션을 조립한다.
- 행사종류와 템플릿은 계속 독립적으로 유지한다.
- 지원되는 범위에서 사용자에게 섹션 ON/OFF 및 순서 변경 기능을 제공할 수 있다.

## 15. T-15 관리자 템플릿 등록/편집

관리자 페이지에서 가능한 한 다음 항목을 등록/수정할 수 있도록 한다.

- 템플릿명 / stable template key
- 디자인 스타일
- 썸네일 / 긴 판매용 미리보기
- Hero 표현 방식, 비율, 마스크
- 배경/프레임/장식 Asset
- 색상/폰트/타이포그래피
- 콘텐츠 폭/간격
- 섹션 스타일/순서/기본 ON·OFF
- 갤러리 스타일
- 스크롤 등장 애니메이션
- 추천 화면 효과
- 추천 BGM
- 추천 행사/분위기 태그
- 정상가/판매가
- 배지, 노출 순서, 판매 상태

- 실제 Renderer 기반 모바일 미리보기를 제공한다.
- 일상적인 템플릿 등록/수정은 Codex → GitHub → Vercel 재배포 없이 관리자에서 처리하는 것을 목표로 한다.
- 관리자 UI는 모바일에서도 실무 운영이 가능하도록 설계한다.

## 16. T-16 템플릿 버전 관리

- 템플릿은 stable `template_id`와 버전 개념을 가진다.
- 이미 발행된 초대장은 사용 당시의 템플릿 버전을 유지한다.
- 큰 디자인 변경은 새 버전으로 저장하고 신규 선택부터 새 버전을 사용한다.
- 과거 버전과 해당 Asset은 이를 참조하는 초대장이 존재하는 동안 보호한다.
- 관리자에서 버전 이력을 확인할 수 있도록 한다.

## 17. T-17 성능·용량 규격

- 첫 화면 Hero와 필수 Asset을 우선 로딩한다.
- 하단 콘텐츠, 갤러리, 지도, 장식 등은 가능한 범위에서 lazy loading한다.
- 이미지 자동 리사이즈/압축 및 반응형 이미지 제공을 지향한다.
- 관리자 Asset 업로드 시 과도한 파일 크기를 검증하고 경고 또는 자동 최적화한다.
- 화면 효과와 스크롤 애니메이션은 모바일 성능을 우선한다.
- BGM은 불필요한 초기 다운로드를 피하고 사용자 상호작용/재생 시점에 맞춰 로딩한다.
- 관리자에서 템플릿 예상 용량 또는 성능 경고를 제공하는 방향을 고려한다.

## 18. T-18 모바일 조작·접근성

- 모바일 우선으로 설계한다.
- 버튼, 지도, 계좌 복사, RSVP 등 터치 영역은 충분한 크기를 확보한다.
- 갤러리 Lightbox는 모바일 Swipe와 자연스러운 닫기/넘기기를 지원한다.
- 작은 스마트폰에서도 텍스트/버튼이 잘리거나 겹치지 않아야 한다.
- 장식/화면 효과 레이어는 포인터/터치 이벤트를 가로채지 않는다.
- `prefers-reduced-motion` 등 사용자 접근성 설정을 존중한다.

## 19. T-19 미리보기와 실제 발행본 일치

- 관리자 미리보기, 사용자 전체 미리보기, 실제 발행본은 가능한 한 동일한 `InvitationRenderer`와 동일한 렌더링 조건을 사용한다.
- RSVP/방명록 등 ON/OFF 섹션도 실제 발행본과 동일하게 미리보기한다.
- 별도의 하드코딩된 가짜 미리보기 화면을 만들지 않는다.
- 판매용 썸네일/긴 홍보 이미지는 상품 소개 Asset이며 실제 렌더링과 분리한다.

## 20. T-20 반응형 테스트 기준

대표 검증 폭은 다음 범위를 포함한다.

- 작은 스마트폰: 320~360px
- 일반 스마트폰: 375~390px
- 큰 스마트폰: 412~430px
- 최대 콘텐츠 폭: 540px

- 540px 초과 화면에서는 중앙 정렬을 유지한다.
- Hero 크롭, 긴 이름/문구, 지도, 달력, 계좌번호, RSVP/방명록, 갤러리, 장식 위치, 애니메이션을 주요 회귀 테스트 대상으로 한다.
- 관리자 미리보기에서 작은폰/일반폰/큰폰 등 대표 화면 폭을 전환해 확인할 수 있도록 한다.

## 21. T-21 Safe Area

- 템플릿별로 핵심 텍스트, 버튼, 얼굴 등이 장식과 겹치지 않는 안전영역을 설정할 수 있도록 한다.
- Hero는 필요 시 top/right/bottom/left 안전영역과 얼굴 권장영역을 정의할 수 있다.
- 관리자 미리보기에서 Safe Area 가이드 표시 ON/OFF를 제공한다.
- 가이드선은 실제 발행본에는 표시하지 않는다.

## 22. T-22 이미지/Asset 파일 형식 및 최적화

- 관리자 업로드 입력은 JPG, PNG, WebP 등을 지원하는 방향으로 한다.
- 웹 제공용 이미지는 가능한 경우 WebP 등 적절한 웹 포맷으로 자동 최적화한다.
- 투명 배경이 필요한 장식/프레임 Asset은 투명도를 보존한다.
- 저해상도 Asset은 화질 경고를 표시한다.
- 과도한 해상도/용량은 자동 리사이즈·압축 또는 업로드 경고/제한을 적용한다.
- 업로드 최대 용량 등 운영값은 관리자 설정으로 조정 가능하도록 설계한다.
- 필요에 따라 원본 Asset과 웹 최적화 Asset을 구분 관리한다.

## 23. T-23 연출 프리셋

- `화면 효과 + 스크롤 등장 애니메이션 + 추천 BGM`을 하나의 연출 프리셋으로 저장할 수 있게 한다.
- 관리자는 프리셋을 생성/수정/비활성화할 수 있다.
- 템플릿에 프리셋을 적용한 후 개별 값을 override할 수 있다.
- 프리셋과 효과/BGM 카탈로그는 데이터 기반으로 확장 가능하게 한다.

## 24. T-24 템플릿 복제

- 관리자는 기존 템플릿을 복제해 새 템플릿의 출발점으로 사용할 수 있다.
- 복제 시 새로운 `template_id`를 발급한다.
- 레이아웃, 폰트, 색상, Hero, 장식 배치, 섹션 설정, 연출 설정 등을 복사한다.
- 복제본은 기본적으로 비공개/미판매 상태로 생성한다.
- 기존 판매이력/고객 초대장 데이터와 분리한다.
- 안전하게 공유 가능한 Asset은 참조 재사용하여 Storage 낭비를 줄이되, 복제본의 변경이 원본을 훼손하지 않도록 한다.

## 25. T-25 판매중지·삭제 규칙

- 템플릿은 물리 삭제보다 상태 기반 관리를 우선한다.
- 기본 상태 흐름은 제작/검수/판매/판매중지/보관 상태를 표현할 수 있도록 한다.
- 판매중지는 신규 선택/구매를 막지만 기존 제작·발행 초대장은 유지한다.
- 기존 초대장이 참조하는 템플릿 버전/Asset은 삭제를 방지한다.
- 판매중지 템플릿은 필요 시 판매 재개할 수 있다.

## 26. T-26 기존 초대장에 대한 관리자 변경 반영 기준

### 현재 버전에서 허용 가능한 유지보수 수정
- 명백한 오타
- 깨진 Asset의 동일 의도 교체
- 잘못된 링크 등 디자인 의도를 변경하지 않는 오류 수정

### 새 버전이 필요한 변경
- 배경/색상/폰트/크기 등 디자인 변경
- Hero 구조/마스크 변경
- 장식 위치/구성 변경
- 섹션 레이아웃 변경
- 스크롤 애니메이션 등 주요 연출 변경

- 관리자 저장 UI에서 `현재 버전 유지보수 수정`과 `새 버전으로 저장`을 구분한다.
- 기존 사용자에게 영향을 줄 가능성이 있는 변경은 새 버전을 권장하거나 필요 시 강제한다.
- 변경 이력과 영향 범위를 기록한다.

## 27. T-27 제작·검수·판매 프로세스

기본 흐름:

`제작중 → 검수대기 → 판매가능 → 판매중`

- 관리자에서 디자인/Asset 설정 후 실제 Renderer로 검수한다.
- 자동 기본검사는 필수 Asset 누락, 과도한 이미지 용량, 주요 반응형 문제 가능성, 폰트/BGM 라이선스 관리 정보, 가격, Hero/마스크, 섹션 구성, 효과/애니메이션 설정 등을 점검하는 방향으로 한다.
- 실제 판매 시작은 관리자 최종 승인 동작을 거친다.

## 28. T-28 추천 행사·검색 태그

- 태그는 오직 추천, 검색, 필터, 정렬을 위한 메타데이터다.
- 템플릿 사용 가능한 행사종류를 제한하지 않는다.
- `결혼식`, `돌잔치`, `생일`, `공연`, `기업행사` 등 행사 추천 태그와 `로맨틱`, `미니멀`, `전통`, `고급`, `모던` 등 분위기 태그를 복수 지정할 수 있다.
- 태그 목록도 관리자에서 추가/수정/정렬/비활성화할 수 있도록 한다.

## 29. T-29 판매용 썸네일·미리보기·실제 샘플

템플릿 상품 노출 자산을 다음과 같이 분리한다.

1. **목록 썸네일**: 템플릿 선택 카드용 대표 이미지
2. **긴 판매용 미리보기 이미지**: 상세 화면에서 전체 분위기와 주요 섹션을 보여주는 홍보용 이미지
3. **실제 샘플 초대장**: 실제 `InvitationRenderer`로 렌더링되어 스크롤 애니메이션, 화면 효과, 갤러리, BGM 등을 체험할 수 있는 샘플

- 썸네일/긴 미리보기는 상품 소개용이며 실제 공개 초대장을 평면 이미지로 대체하지 않는다.
- 관리자는 세 자산/데이터를 각각 등록·교체할 수 있도록 한다.
- 판매용 이미지는 업로드 시 웹용으로 최적화한다.

## 30. T-30 관리자 제작 범위와 코드 개발 경계

### 관리자만으로 처리하는 것을 목표로 하는 범위
- 배경/프레임/장식 Asset
- Hero 비율/마스크
- 색상/폰트/글자 크기
- 장식 위치
- 섹션 순서/스타일
- 갤러리 스타일
- 스크롤 등장 애니메이션
- 화면 효과/BGM 추천
- 태그/썸네일/미리보기
- 가격/판매 상태/노출 순서/배지

### 별도 개발이 필요한 범위
- 기존 Renderer가 지원하지 않는 새로운 기능
- 완전히 새로운 구조/인터랙션
- 새로운 공통 섹션 기능
- 기존 설정 모델로 안전하게 표현할 수 없는 렌더링 능력

원칙: **새로운 디자인은 관리자에서, 새로운 기능/Renderer 능력은 개발에서.**

## 31. 화면 효과 상세 규격

초대장 편집 화면에서 사용자가 화면 효과 사용 여부와 효과 종류를 직접 선택할 수 있도록 한다.

- `화면 효과 사용` ON/OFF를 제공한다.
- ON 시 DearDay가 제공하는 효과 중 기본적으로 1개를 선택한다.
- 초기 후보: 벚꽃잎, 눈송이, 반딧불, 별빛, 빛가루, 단풍잎, 장미/꽃잎, 비눗방울, 민들레 홀씨 등.
- 벚꽃/눈/단풍은 떨어짐, 반딧불/빛가루는 부유, 별빛은 반짝임, 비눗방울은 상승 등 효과 특성에 맞는 움직임을 사용할 수 있다.
- 효과는 글 읽기와 버튼 조작을 방해하지 않는 은은한 강도와 적은 개수를 기본으로 한다.
- 효과 레이어는 클릭/터치를 방해하지 않는다.
- 과도한 particle 수와 무거운 애니메이션을 피한다.
- 템플릿에는 추천 효과를 지정할 수 있지만 강제하지 않는다.
- 사용자는 다른 효과를 선택하거나 끌 수 있다.

## 32. 배경음악 상세 규격

- 편집 화면에서 `배경음악 사용` ON/OFF를 제공한다.
- ON 시 DearDay BGM 라이브러리에서 1곡을 선택할 수 있도록 한다.
- 편집 화면에서 미리듣기를 지원한다.
- 분류 예시: 로맨틱 피아노, 따뜻한 어쿠스틱, 여름 감성, 전통/국악, 클래식, 어린이 파티, 재즈, 기업행사 등.
- 템플릿에는 추천 BGM을 지정할 수 있으나 사용자 선택을 제한하지 않는다.
- 상업적 이용 및 DearDay 서비스 내 사용 권리가 명확히 확인된 음원만 등록한다.
- 음원별 라이선스 출처/권리 범위 등 관리 정보를 추적할 수 있도록 한다.
- 모바일 브라우저 자동재생 제한을 고려해 `음악과 함께 보기` 또는 첫 사용자 상호작용 이후 재생 등의 UX를 사용한다.
- 적절한 기본 음량과 재생/정지 제어를 제공한다.

## 33. 데이터/운영 원칙

- 화면 효과, BGM, 스크롤 애니메이션, 폰트, 태그, 연출 프리셋 등 운영 카탈로그는 가능한 한 데이터 기반으로 확장한다.
- 템플릿 추천값과 사용자 초대장 실제 선택값은 구분한다.
- 같은 템플릿에서도 사용자마다 다른 허용된 효과/BGM 선택을 사용할 수 있다.
- 가격/판매 상태/노출 순서/배지 등 상품 운영값 역시 관리자 페이지 관리 원칙을 따른다.
- 보안, 권한, 결제 검증, Renderer 핵심 안전장치 등은 서버/코드가 책임진다.

## 35. 현재 구현 체크포인트 / Config 단계 (2026-09-20)

⑬-T2 관리자 템플릿 편집은 다음 단계로 나누어 진행한다.

- **C1 Decoration Config — 완료**: 장식 Asset의 slot, X/Y, size, rotation, opacity, zIndex, visible을 Draft Version config에 저장/복원한다.
- **C2 Background + Hero Config — 완료**: 전체 Background와 Hero Background를 독립 설정하며 color/asset/overlay와 Hero mode/aspectRatio/positionX/positionY/zoom/frame을 Draft Version config에 저장/복원한다.
- **C3 Typography + Colors — 다음 작업**: Hero Title, Section Title, Body, Caption/Small 등 역할별 폰트·크기·굵기·행간·자간·정렬과 기본/제목/포인트/버튼 등 색상 설정을 안전 범위 내에서 관리자 편집 가능하게 한다.
- **C4 Sections**: 공통 섹션의 기본 순서와 기본 ON/OFF를 템플릿 config로 관리한다.
- **C5 Effects/BGM/Safe Area**: scroll reveal, 추천 화면효과, 추천 BGM, Safe Area 등 고급 config를 관리한다.
- **C6 Renderer 연결**: C1~C5에서 저장한 config를 기존 공통 InvitationRenderer에 연결한다. C6는 ⑬-T3의 핵심 구현으로 취급한다.

### Background Asset 운영 정책

- `background`과 `decoration` Asset은 여러 개를 동시에 active 상태로 둘 수 있다.
- 전체 Background의 `background.assetId`와 Hero의 `hero.backgroundAssetId`는 서로 독립적으로 선택한다.
- 같은 Background Asset ID를 전체 Background와 Hero에서 함께 사용하는 것을 기본적으로 허용한다.
- 같은 이미지를 사용하더라도 전체 Background와 Hero의 overlay color/opacity 등 표현값을 독립 조정해 자연스럽게 연결할 수 있다.
- 판매용 템플릿의 Asset 개수를 7개로 하드코딩하지 않는다. 기존 7종 기본 체계는 유지하되, 별도 Hero Background가 디자인상 필요한 경우에만 추가 Background Asset을 등록한다.
- 따라서 모든 기존 판매용 템플릿에 일괄적으로 8번째 Asset을 추가 생성하지 않는다.

### Draft Config 보존 원칙

- C1~C5는 동일한 `template_versions.config`를 단계적으로 확장한다.
- 한 Config 영역을 저장할 때 다른 영역의 기존 값을 삭제하거나 초기화하지 않는다.
- 실질적 디자인 변경은 Draft Version에서 편집하고, 판매중 버전 및 기존 발행 초대장의 version pin을 직접 변경하지 않는다.


## 관리자 Draft Live Preview 선행 체크포인트 (2026-09-21)

- C1~C5 관리자 Draft Config 저장 기반은 완료되었다: Decoration, Background/Hero, Typography/Colors, Sections, Effects/BGM/Safe Area.
- C6-1에서 Template Config normalization 기반을 추가했고, C6-2에서 공개 초대장이 이벤트에 pin된 `template_version_id`의 Config를 읽어 Background/Hero/Typography/Colors를 적용하는 경로를 구현했다.
- 공개 렌더링은 `current_sale_version_id`를 따라가지 않으며, 과거 pinned Version이 참조하는 Asset은 현재 `is_active=false`여도 유효한 참조라면 보호한다.
- 현재 테스트 템플릿은 판매 버전 없이 Draft만 존재하므로, Draft 디자인의 실화면 검증을 위해 관리자 Live Preview를 C6 후반에서 **C6-3 이전으로 선행**한다.
- 관리자 Live Preview는 실제 `InvitationRenderer`를 그대로 재사용해야 하며 별도의 축약/가짜 Renderer를 만들지 않는다.
- Preview 입력은 현재 편집 중인 Draft Version Config + 해당 Template Asset + 안전한 샘플 invitation data를 사용한다. 공개 발행본의 pinned Version 데이터 흐름은 변경하지 않는다.
- Config 입력은 기존 숫자/선택 UI를 유지하고 Preview에서 결과를 확인한다. MVP에서 직접 Drag/Resize 편집은 구현하지 않는다.
- Preview 선행 후 진행 순서: C6-2 시각 TC → C6-3 Decoration/Sections → C6-4 Effects/Safe Area → C6 통합 회귀 → T4 버전/판매상태 마무리.
- BGM은 실제 음원/플레이어 기반이 없으므로 현재 `mode=none`만 유지하며 Live Preview에서 재생 기능을 새로 만들지 않는다.
