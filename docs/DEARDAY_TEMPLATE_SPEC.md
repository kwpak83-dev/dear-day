# DearDay 판매용 템플릿 규격 초안

> 목적: 향후 관리자 페이지에서 판매용 템플릿을 직접 등록할 때 사용할 공통 디자인/이미지 구조를 정의한다.
> 이 문서는 ⑬ 관리자 페이지 및 ⑬-A 판매용 템플릿 확대 구현 시 기준으로 사용한다.

## 1. 기본 등록 이미지

템플릿 1개 등록 시 기본 상품 이미지는 다음 2장을 기준으로 한다.

1. **썸네일 이미지**: 템플릿 선택 목록에서 사용하는 대표 이미지
2. **전체 미리보기 이미지**: 템플릿 상세/미리보기에서 전체 분위기와 섹션 디자인을 보여주는 긴 세로형 이미지

이 2장은 판매 상품을 보여주기 위한 이미지이며 실제 공개 초대장 화면을 평면 이미지로 대체하지 않는다. 실제 초대장은 공통 `InvitationRenderer`가 사용자 데이터와 템플릿 디자인 설정을 조합해 렌더링한다.

## 2. 대표사진 표현 방식

템플릿은 대표사진 표현 방식을 디자인 특성에 따라 구분할 수 있도록 설계한다.

### A. 사진 중심형

- 미니멀/모던 등 사용자 대표사진 자체가 디자인의 중심인 템플릿에 사용한다.
- 대표사진을 메인 영역에 크게 배치한다.
- 템플릿 장식은 사진을 방해하지 않는 범위에서 적용한다.

### B. 컨셉 프레임형

- 일본 시골 여름, 한옥/한복, 중세 유럽, 어린이 판타지 등 고유한 세계관·배경이 상품 가치의 핵심인 템플릿에 사용한다.
- 사용자가 대표사진을 업로드해도 템플릿의 고정 컨셉 배경이 사라지지 않아야 한다.
- **사용자 대표사진은 주인공 영역, 고정 컨셉 배경은 사진을 둘러싼 액자/무대 역할**을 하도록 구성한다.
- 하늘, 노을, 기차역, 한옥, 성, 꽃, 구름, 풍선 등의 컨셉 요소는 템플릿 자산으로 유지한다.
- 사용자 사진과 고정 배경의 경계에는 꽃, 빛 번짐, 수채화 번짐, 그라데이션, 장식 프레임 등을 활용해 자연스럽게 연결할 수 있다.
- 단순한 네모 액자만을 의미하지 않으며, 사용자 사진이 해당 세계관 안에 자연스럽게 들어온 것처럼 보이는 표현을 지원하는 방향으로 설계한다.

### C. 포스터/일러스트형

- 대표사진 없이도 완성되는 일러스트·포스터 중심 템플릿을 위한 선택 구조로 고려한다.
- 사용자가 사진을 사용하지 않는 경우에도 디자인 완성도가 유지되어야 한다.

## 3. 컨셉 배경과 사용자 사진의 분리

향후 템플릿 규격에서는 다음 요소를 논리적으로 분리한다.

- `사용자 대표사진`: 초대장 소유자가 업로드하는 동적 데이터
- `컨셉 배경`: 템플릿에 포함되는 고정 디자인 자산
- `프레임/마스크`: 대표사진의 위치, 비율, 모양, 크롭 영역
- `오버레이 장식`: 꽃, 빛, 구름, 프레임 등 사용자 사진 위/주변에 겹쳐지는 템플릿 자산
- `텍스트 영역`: 이름, 행사일, 장소 등 실제 사용자 데이터가 표시되는 안전 영역

따라서 컨셉형 템플릿에서 사용자가 대표사진을 교체해도 핵심 배경과 세계관은 그대로 유지되어야 한다.

## 4. 향후 관리자 등록 구조

관리자 템플릿 등록 시 장기적으로 다음 항목을 지원하는 방향으로 설계한다.

- 템플릿명 / stable template key
- 디자인 스타일
- 썸네일 이미지
- 전체 미리보기 이미지
- 대표사진 표현 방식 (`photo` / `concept-frame` / `poster` 등)
- 대표사진 프레임/마스크 설정
- 고정 컨셉 배경 및 필요한 장식 asset
- 디자인 theme/layout 설정
- 정상가 / 판매가
- 선택적 추천 행사 태그
- 추천 화면 효과
- 추천 배경음악
- `NEW` / 추천 / 인기 배지
- 노출 순서
- 판매 ON/OFF

추천 행사 태그는 추천·검색·정렬용 메타데이터일 뿐 사용 가능한 행사종류를 제한하지 않는다. 템플릿과 행사종류는 계속 독립적으로 유지한다.

## 5. 디자인 제작 원칙

앞으로 판매용 디자인 시안을 만들 때 처음부터 다음을 구분해서 설계한다.

- 어디까지가 **고정 템플릿 배경/장식**인지
- 어디가 **사용자 대표사진 영역**인지
- 사용자 사진이 바뀌어도 해당 템플릿의 핵심 컨셉이 유지되는지
- 텍스트가 실제 사용자 데이터로 교체되어도 레이아웃이 유지되는지

특히 컨셉형 디자인은 시안 단계부터 `사용자 대표사진 + 고정 세계관 배경` 구조를 기본 방향으로 한다.

## 6. 구현 원칙

- 공통 Renderer + 안전한 버전형 theme/layout config + 승인된 이미지 asset 구조를 우선한다.
- 관리자에게 임의 HTML/JavaScript/CSS 업로드를 허용하는 범용 페이지 빌더 방식은 지양한다.
- 공통 규격으로 표현할 수 없는 완전히 새로운 레이아웃이나 특수 인터랙션만 별도 코드 개발 대상으로 분리한다.
- 실제 이미지 크기, 비율, 파일 형식, 최대 용량, 프레임 좌표/마스크 규격 등 세부 수치는 ⑬/⑬-A 구현 시 모바일 렌더러 기준으로 최종 확정한다.

## 7. 화면 효과

초대장 편집 화면에서 사용자가 화면 효과 사용 여부와 효과 종류를 직접 선택할 수 있도록 한다.

- `화면 효과 사용` 체크박스를 제공한다.
- 체크 해제 시 효과 없이 표시한다.
- 체크 시 DearDay가 제공하는 화면 효과 중 **1개를 선택**할 수 있도록 한다.
- 초기 후보: 벚꽃잎, 눈송이, 반딧불, 별빛, 빛가루, 단풍잎, 장미/꽃잎, 비눗방울, 민들레 홀씨 등.
- 효과별 움직임은 특성에 맞게 다르게 표현할 수 있다. 예: 벚꽃/눈/단풍은 떨어짐, 반딧불/빛가루는 부유, 별빛은 반짝임, 비눗방울은 상승.
- 효과는 글 읽기와 버튼 조작을 방해하지 않도록 **은은한 강도와 적은 개수**를 기본 원칙으로 한다.
- 화면 효과 레이어는 클릭/터치 등 사용자 인터랙션을 방해하지 않아야 한다.
- 모바일 성능을 고려해 과도한 particle 수와 무거운 애니메이션을 피한다.
- 동시에 여러 효과를 중복 적용하지 않고 기본적으로 1개만 선택하도록 한다.
- 템플릿에는 `추천 화면 효과`를 지정할 수 있으며 편집 화면에서 추천 표시할 수 있다.
- 추천 효과는 강제가 아니며 사용자는 다른 효과를 선택하거나 완전히 끌 수 있다.
- 향후 편집 화면에서 선택 즉시 미리보기로 확인할 수 있는 구조를 고려한다.

## 8. 배경음악

초대장 편집 화면에서 사용자가 배경음악 사용 여부와 음악을 직접 선택할 수 있도록 한다.

- `배경음악 사용` 체크박스를 제공한다.
- 체크 해제 시 공개 초대장은 무음으로 동작한다.
- 체크 시 DearDay가 제공하는 BGM 라이브러리에서 1곡을 선택할 수 있도록 한다.
- 편집 화면에서 각 곡을 **미리듣기** 할 수 있도록 한다.
- 음악 분류 예시: 로맨틱 피아노, 따뜻한 어쿠스틱, 여름 감성, 전통/국악, 클래식, 어린이 파티, 재즈, 기업행사 등.
- 템플릿에는 `추천 배경음악`을 지정할 수 있으며 편집 화면에서 추천 표시할 수 있다.
- 추천 BGM은 강제가 아니며 사용자는 다른 음악을 선택하거나 완전히 끌 수 있다.
- DearDay가 상업적으로 서비스하는 초대장에서 사용할 수 있도록 **상업적 이용 및 서비스 내 사용 권리가 명확히 확인된 음원만 등록**한다.
- 음원별 라이선스 출처/권리 범위 등 관리 정보는 향후 관리자 구조에서 추적 가능하도록 고려한다.
- 모바일 브라우저의 오디오 자동재생 제한을 고려한다. 필요 시 공개 초대장에서 `음악과 함께 보기` 또는 첫 사용자 상호작용 이후 재생하는 UX를 사용한다.
- 음악은 초대장 콘텐츠 열람을 방해하지 않도록 적절한 기본 음량과 간단한 재생/정지 제어를 제공하는 방향으로 설계한다.

## 9. 템플릿 추천 효과/BGM 운영 원칙

- 관리자가 판매용 템플릿 등록/수정 시 `추천 화면 효과`와 `추천 배경음악`을 설정할 수 있도록 한다.
- 예: 봄/일본 감성 템플릿 → 벚꽃잎 + 잔잔한 피아노, 한옥/전통 템플릿 → 꽃잎/빛가루 + 잔잔한 국악 등.
- 추천값은 템플릿의 기본 분위기를 제안하기 위한 것이며 사용자 선택을 제한하지 않는다.
- 화면 효과와 BGM은 템플릿 자체와 분리된 사용자 설정으로 저장하여, 같은 템플릿에서도 사용자마다 다른 선택을 사용할 수 있도록 한다.
- 향후 새로운 효과/BGM을 추가해도 기존 템플릿 코드 수정이 최소화되도록 데이터/설정 기반 확장 구조를 지향한다.
