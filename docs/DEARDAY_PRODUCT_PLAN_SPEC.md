# DearDay 상품·요금제 운영 규격

> 목적: ⑫-A 요금제 구조, ⑫-B 이용권 관리, ⑬ 관리자 페이지, ⑭ 실제 결제 구현 시 적용할 상품/이용권 운영 정책을 정의한다.
>
> 운영 원칙: 운영 중 변경될 가능성이 있는 값은 가능한 한 코드에 하드코딩하지 않고 DB + 관리자 페이지에서 관리한다. 인증/권한, 결제 검증, 발행/이용권 차감 무결성 등 보안·핵심 시스템 로직은 코드에서 보호한다.

## 1. 상품 구조 기본 원칙

- DearDay 상품은 시스템에서 `B2C 단건`과 `B2B 전용`으로 경직되게 구분하지 않는다.
- `Partner 50`, `Partner 100` 같은 이름은 마케팅/판매용 상품명일 뿐 구매 자격을 의미하지 않는다.
- 다건 이용권은 개인과 사업자 모두 구매할 수 있다.
- 현재 기본 정책은 모든 사용자가 다건 상품을 구매할 수 있는 구조다.
- 향후 특정 회원군 전용 상품이 필요할 경우 구매 대상 정책을 확장할 수 있도록 설계한다.
- 최초 오픈 시 판매용 템플릿은 모두 유료로 운영하고 영구 무료 템플릿은 두지 않는다. 프로모션용 무료 발행권은 별도 정책으로 운영 가능하다.
- 초기에는 모든 일반 판매 템플릿에 공통 단건 가격을 적용한다. 공통 단건 가격은 관리자에서 변경 가능해야 하며 특정 금액을 코드에 고정하지 않는다.
- 향후 프리미엄 템플릿별 가격 확장이 가능하도록 구조적 여지는 둔다.

## 2. 관리자 상품 관리

운영자는 모바일 관리자 페이지에서도 다음을 관리할 수 있어야 한다.

- 상품 신규 추가
- 상품명/설명 수정
- 정상가(선택) / 판매가 설정
- 포함 발행 건수 설정
- 이용권 유효기간 또는 무기한 설정
- 노출/숨김, 판매 ON/OFF
- 상품 노출 순서 직접 지정
- `BEST`, `추천`, `인기`, `할인`, `NEW` 등 배지 설정/해제
- 필요 시 향후 구매 대상 정책 설정

상품명과 수량은 코드에 고정하지 않는다. 예: `10회 이용권`, `웨딩홀 100`, `가을 프로모션 30` 등 운영자가 자유롭게 생성/변경할 수 있다. 표시 이름이 변경되어도 내부의 안정적인 `product_id`는 유지한다.

상품 카드에서는 정상가와 판매가가 모두 존재하면 할인율을 자동 계산해 표시하고, 다건 상품은 `판매가 ÷ 포함 건수`로 건당 가격을 자동 표시한다. `단건 구매 대비 총 ○○원 절약` 문구는 기본 표시하지 않는다. 유효기간은 구매 전 상품 카드에서 `결제일로부터 365일` 또는 `유효기간 없음`처럼 명확하게 표시한다.

사용자가 임의의 수량을 입력해 구매하는 기능은 두지 않고 관리자가 등록한 정액 상품만 판매한다. 한 결제에서는 상품 1개만 구매하며 동일 상품을 여러 수량으로 묶어 구매하거나 단건 발행과 이용권 상품을 장바구니식으로 혼합 결제하지 않는다. 동일 상품 자체는 횟수 제한 없이 반복 구매할 수 있다.

## 3. 기존 구매자 보호 / 판매 종료

- 주문 완료 시 상품명, 결제 금액, 정상가/판매가, 포함 건수, 유효기간 및 적용 조건을 구매 스냅샷으로 보존한다.
- 이후 관리자가 상품명·가격·건수·유효기간을 변경해도 기존 구매자의 조건은 바뀌지 않는다.
- 상품 판매중지는 신규 구매만 막고 기존 구매자의 잔여 이용권과 권리는 유지한다.
- 상품 삭제는 물리 삭제보다 비활성화/숨김을 기본으로 하며 과거 주문·이용권·스냅샷을 보존한다.

## 4. 이용권 부여 및 유효기간

- 다건 이용권의 유효기간은 결제 완료 시점부터 시작한다.
- 관리자는 상품별 유효기간을 설정하거나 `유효기간 없음`으로 만들 수 있다.
- 유효기간이 지나면 해당 구매 배치의 미사용 잔여 이용권은 자동 소멸한다.
- 사용자가 같은 상품 또는 다른 다건 상품을 추가 구매하면 기존 잔여분에 단순 합산하지 않고 각 구매를 별도 배치(batch)로 관리한다.
- 각 배치는 구매일, 최초 제공 수량, 잔여 수량, 유효기간/만료일, 구매 스냅샷을 유지한다.
- 이용권 사용 시 유료/무료 출처와 관계없이 유효한 이용권 중 가장 먼저 만료되는 배치부터 사용한다. 무기한 이용권은 만료일이 있는 이용권 뒤에 사용한다.
- 이용권은 다른 계정으로 양도하거나 선물할 수 없다.
- 판매가 중단된 상품의 기존 이용권도 원래 조건대로 계속 사용할 수 있다.

## 5. 발행과 이용권 차감

- 이용권은 초대장 제작 시작, 저장, 미리보기 단계에서는 차감하지 않는다.
- **새로운 초대장의 최초 최종 발행이 실제로 성공한 순간에만 1건을 차감한다.**
- 동일 `invitation_id`는 최초 성공 발행에 대해서만 1회 차감한다.
- 이미 발행된 초대장을 중지했다가 다시 공개해도 추가 차감하지 않는다.
- 이미 차감된 발행 초대장을 삭제해도 이용권을 복원하지 않는다.
- 발행 후 이름, 날짜, 장소, 사진, 문구 등 내용을 수정해도 추가 차감하지 않는다.
- 기존 정책에 따라 발행 후 템플릿 변경은 허용하지 않는다.
- 여러 초대장을 선택해 일괄 발행하는 기능은 초기에는 두지 않고 초대장별로 하나씩 발행/차감한다.

사용 가능한 이용권이 존재하면 단건 결제를 선택하게 하지 않고 자동으로 이용권 1건을 사용한다. 여러 배치가 있으면 가장 먼저 만료되는 유효 배치에서 차감한다. 이용권이 없으면 단건 결제 → 발행이 기본 흐름이며, 이 결제 화면에서 다건 이용권 상품도 함께 안내할 수 있다.

발행 과정에서 사용자가 다건 상품을 구매한 경우 `결제 성공 → 이용권 배치 부여 → 해당 초대장에 1건 차감 → 최종 발행`을 하나의 자연스러운 흐름으로 처리하고 다시 발행 버튼을 누르게 하지 않는다. 이 과정은 서버에서 트랜잭션/멱등성(idempotency)을 고려해 결제 성공 후 권리 유실이나 중복 차감이 없도록 구현한다.

## 6. 구매 경로

다건 이용권 상품은 다음 두 경로에서 구매할 수 있다.

1. 별도의 요금제/이용권 페이지
2. 초대장 최종 발행 과정에서 사용 가능한 이용권이 없을 때 표시되는 결제 화면

한 결제에는 단건 발행 또는 다건 이용권 상품 중 한 종류의 거래만 처리한다.

## 7. 이용권 잔여량 / 사용자 이력

- 이용권 잔여량은 마이페이지와 초대장 제작/발행 화면 양쪽에서 확인할 수 있어야 한다.
- 발행 직전에는 필요 시 `23건 보유 → 발행 후 22건`처럼 예상 차감을 보여준다.
- 마이페이지 상단에는 총 잔여 건수와 가장 가까운 만료 정보를 함께 표시한다. 예: `총 58건 보유 · 이 중 8건이 2026.10.01 만료 예정`.
- 마이페이지에는 잔여량뿐 아니라 구매/사용/조정/만료 이력을 제공한다.
- 예: 구매 `+50`, 최초 발행 `-1`, 관리자 지급 `+5`, 관리자 회수 `-2`, 만료 `잔여 8건 소멸`.
- 만료되어 잔여 수량이 소멸된 뒤에도 해당 이력은 삭제하지 않고 사용자 및 관리자 확인용으로 보존한다.

## 8. 관리자 이용권 조정 / 무료 지급

관리자는 고객지원·프로모션·보상·파트너 테스트 등의 목적으로 이용권을 수동 지급하거나 회수할 수 있다.

관리자 조정에는 최소 다음을 기록한다.

- 조정 수량
- 조정 사유
- 처리 관리자
- 처리 시각
- 조정 전/후 잔여량

무료 지급 배치에는 관리자가 수량과 유효기간을 설정할 수 있다. 유료 구매 배치와 관리자 무료 지급 배치는 이력에서 구분한다. 실제 사용 우선순위는 유료/무료 여부가 아니라 만료일 우선 원칙을 따른다.

## 9. 환불 정책 방향

- 이용권을 한 건도 사용하지 않은 경우 정해진 환불 가능 기간/조건 안에서 전액 환불하는 방향으로 한다.
- 이용권이 1건이라도 실제 발행에 사용된 다건 상품은 상품 전체 환불 불가를 기본 운영 정책 방향으로 한다.
- 정확한 환불 가능 기간, 전자상거래/디지털콘텐츠 관련 법적 요건, PG사 취소·환불 규칙은 실제 오픈 전 별도 검토하여 최종 확정한다.
- 시스템은 사용량, 최초 사용 시각, 구매 스냅샷 등 환불 판단에 필요한 근거를 보존한다.

## 10. 이용권 만료 알림

- 만료 안내는 초기에는 이메일을 기본 채널로 사용하고 카카오 알림톡은 향후 확장으로 둔다.
- 마이페이지에서는 이메일 발송 여부와 무관하게 잔여 이용권과 만료일을 항상 확인할 수 있어야 한다.
- 관리자는 만료 이메일 기능 전체를 ON/OFF할 수 있다.
- 관리자는 `30일 전`, `7일 전`, `1일 전`처럼 발송 시점을 코드 수정 없이 자유롭게 설정할 수 있고 여러 시점을 등록할 수 있다.
- 사용자는 마이페이지에서 본인의 이용권 만료 이메일 수신을 ON/OFF할 수 있다.
- 사용자는 소셜 로그인 이메일과 별도로 알림용 이메일 주소를 등록/변경할 수 있다.
- **알림용 이메일 변경 시 인증번호/인증링크 인증을 필수로 할지는 결정 43에서 보류되었으며 구현 시 재검토한다.**

## 11. 이용권 유효기간 연장

- 고객이 직접 결제하여 기존 이용권의 유효기간을 연장하는 셀프서비스 기능은 초기에는 제공하지 않는다.
- 만료 후 필요하면 새 상품을 구매하는 것이 기본 흐름이다.
- 고객지원 등 예외 상황에서는 관리자가 이용권 만료일을 수동 연장할 수 있다.
- 관리자 연장 시 기존 만료일, 변경된 만료일, 사유, 관리자, 처리 시각을 감사 로그에 남긴다.

## 12. 초대장 복제

- 모든 사용자는 본인이 만든 초대장을 복제할 수 있다. 이용권 보유자만의 기능으로 제한하지 않는다.
- 복제 자체는 무료이며 복제 횟수 제한도 두지 않는다.
- 복제본은 새로운 `invitation_id`를 가진 미발행 초안이다.
- 원본의 디자인, 입력 내용, 사진을 복제한다.
- RSVP 응답, 방명록, 기존 URL/slug, 결제 이력, 발행 이력은 복제하지 않는다.
- 복제본이 최초 발행에 성공할 때 단건 결제 또는 이용권 1건을 새로 사용한다.
- 사진 복제 구현 시 불필요한 Storage 중복을 최소화하되, 원본 삭제가 복제본 사진을 깨뜨리지 않도록 파일 참조/소유권 정책을 안전하게 설계한다.

## 13. 제작 중 초안 개수 제한

- 계정당 미발행 제작 중 초대장 수에는 제한을 둔다.
- 기본 최대값은 **10개**로 한다.
- `10`을 코드에 하드코딩하지 않고 DB 운영 설정으로 관리하며 모바일 관리자 페이지에서 변경할 수 있어야 한다.
- 관리자가 최대값을 낮췄을 때 이미 새 제한보다 많은 초안을 가진 사용자의 기존 초안을 강제로 삭제하지 않는다. 사용자의 초안 수가 새 제한 미만이 될 때까지 신규 초안 생성만 막는다.

## 14. 미발행 초안 자동 정리

- 장기간 방치된 미발행 초안은 자동삭제 대상으로 한다.
- 기본 기준은 **마지막 실제 수정·저장 또는 사용자의 명시적 보관기간 연장 시점으로부터 90일**이다.
- `90일` 역시 하드코딩하지 않고 관리자 페이지에서 변경 가능하게 한다.
- 단순히 초안을 열거나 조회하는 행위만으로 보관 기준일을 갱신하지 않는다.
- 실제 수정 후 저장이 성공하면 보관 기준일을 갱신한다.
- 삭제 예정 사용자는 사전에 이메일로 안내하며, 삭제 전 알림 시점과 횟수는 관리자에서 자유롭게 설정한다.
- 사용자는 `보관기간 연장` 기능을 통해 내용을 억지로 수정하지 않고도 보관 기준일을 갱신할 수 있다.
- 보관기간 연장 횟수는 제한하지 않는다.
- 자동삭제 시 초안 DB 데이터만 삭제하고 끝내지 않고 해당 초안이 소유하는 불필요한 Storage 사진/파일도 안전하게 정리한다. 다른 초대장과 공유 참조되는 파일은 참조 무결성을 확인한 뒤 삭제한다.

## 15. 하드코딩 금지 / 모바일 관리자 원칙

다음처럼 운영 중 바뀔 수 있는 값은 가능한 한 DB + 관리자 페이지에서 관리한다.

- 공통 단건 가격
- 다건 상품명/설명/가격/건수/유효기간
- 상품 판매 여부/노출 여부/순서/배지
- 초안 최대 개수
- 초안 자동삭제 기간
- 초안 삭제 사전 알림 시점
- 이용권 만료 이메일 ON/OFF 및 발송 시점
- 향후 템플릿 가격/추천 설정 등 운영 값

관리자 페이지는 모바일 우선으로 설계하여 노트북 없이도 주요 운영이 가능하도록 한다. 중요한 변경에는 확인 절차, 변경 전/후 값 표시, 관리자/시각/사유 등의 감사 로그를 적용한다.

인증/권한, 결제 금액 서버 검증, 발행 성공 판정, 이용권 부여/차감, 중복 결제/중복 차감 방지, 데이터 삭제 안전장치 등은 관리자 설정값으로 우회할 수 없는 서버 핵심 로직으로 보호한다.
